**版本 1.0 ｜ 2026-08-17 ｜ 適用版本：Kimi 部署版與 GitHub 自架版（pcpcchen-coder/AIDCalculator）**

---

## 第 1 章　關於本系統

### 1.1 這是什麼？

DCGen Web 是依據 DCGen 1.1 技術報告（arXiv:2604.09616，芝加哥大學／阿貢國家實驗室）與其開源實作打造的**資料中心硬體配置產生平台**。輸入資料中心的類型與規模目標，系統會自動算出：

- **IT 配置**：各節點型別（GPU、CPU-GPU、CPU、Storage）需要多少機架、峰值功率多少 MW、功率密度（kW/m²）、需要多少 White space（IT 樓板面積 m²）。
- **冷卻系統**：CDU、冰水機、乾冷卻器／冷卻水塔各需要幾台、選哪個市售型號、耗電多少。
- **配電系統**：PDU、UPS、MSB（主配電盤）、備援發電機各需要幾台（含 N+1／2N／xN-y 冗餘與安全餘裕）、轉換損耗多少。
- **Gray space**：冷卻與配電基礎設施佔地（室內／室外 m²）。

### 1.2 系統能做的事（對應頁面）

| 需求 | 去哪裡做 |
|---|---|
| 產生一個資料中心配置、看結果圖表 | 配置產生器 `/generator` |
| 儲存情境、之後重開、多情境並排比較 | 配置產生器下方「已存情境」 |
| 瀏覽/新增/編輯/刪除設備型錄（含台達電子產品）或 IT 參考配置 | 資料庫管理 `/catalog` |
| 調整模型參數（如安全餘裕預設值）、新增自己的參數 | 參數管理 `/parameters` |
| 查看論文式 1–19 算法、調整算法、新增自己的算法公式並試算 | 算法管理 `/algorithms` |
| 了解 DCGen 模型、冗餘語彙、資料來源 | 模型說明 `/docs` |

### 1.3 三分鐘名詞速覽

| 名詞 | 白話解釋 |
|---|---|
| White space | 放 IT 機架的樓板面積（m²） |
| Gray space | 放冷卻、配電設施的面積（分室內/室外） |
| 功率密度 | 每平方公尺用多少 kW（衡量同空間能塞多少功率） |
| Canonical 配置 | 論文把多個真實系統平均後的「標準配置」（2024/2027/2029 三個年代） |
| Reference 配置 | 真實系統（如 xAI COLOSSUS、DGX SuperPOD、Aurora） |
| 冗餘 N+1 / 2N / xN-y | 需要 N 台則多備 r 台；2N = 兩套全備；xN-y = 每台只交付 y/x 容量 |
| 安全餘裕 (sm) | 設備再多超配的比例（0.2 = 多 20%） |
| pod | 機架群組單位 = rows_per_pod × rack_per_row（預設 2×10 = 20 架/pod），CDU/PDU 以 pod 為單位配置 |
| engineEligible | 型錄開關：該設備是否參與自動選型 |

## 第 2 章　五分鐘快速上手

**目標：產生你的第一個配置——1,000 機架的 AI 訓練資料中心。**

1. 開啟網站，點左側欄「**配置產生器**」。
2. 表單基本上用預設值即可：
   - 資料中心類型：**AI 訓練**
   - 目標：**機架數** `1000`
   - 模型別：**Canonical**、年份 **2024**
   - 散熱模式：**乾式冷卻**；優化目標：勾 **Space** 和 **Power**
   - 冗餘：預設（冷卻側 N+1、配電側 2N）；安全餘裕 20%
3. 按「**產生配置**」。右側儀表板會出現結果。
4. **對照預期結果**（這組數字已與原版 Python DCGen 對拍驗證）：
   - IT 峰值功率 ≈ **143.6 MW**（GPU 888 架 / 140.3 MW＋Storage 112 架 / 3.3 MW）
   - 功率密度 ≈ **79.8 kW/m²**；White space = **1,800 m²**；共 **50 個 pod**
   - Power 優化：乾冷卻器 Vertiv Liebert \*D\*\*112 × **4,983 台**、冰水機 × 385、CDU CoolIT CHx2000 × 150（每 pod 3 台），冷卻功耗 ≈ **26.6 MW**
   - UPS（IT 階段）= 台達 Modulon DPH-G3-1250K × **276 台**（注意：台達產品在 BOM 表有綠點標記）
5. 按右上「**儲存情境**」→ 命名（如「AI 訓練 1000 架 2024」）→ 之後可隨時重開或拿來比較。

> 如果數字對不起來：到「參數管理」按「還原全部預設」再試一次（你可能改過全域參數）。

## 第 3 章　介面總覽

### 3.1 版面結構

- **左側欄**（240px）：六個頁面連結＋版本徽章＋論文/REPO 外鏈；手機版為頂列漢堡選單。
- **頁首**（每頁上方）：麵包屑、頁面標題、一句話說明、右側主動作按鈕（如「新增資料」「產生配置」）。
- **主內容區**：各頁功能區。

### 3.2 通用元件語意

| 元件 | 用法 |
|---|---|
| 表格 | 點欄標可排序；點列可展開詳情；hover 顯示更多操作 |
| 徽章（Badge） | 分類色：cyan=Canonical/內建、violet=Reference/自訂、amber=已修改/警告、綠=台達電子/成功 |
| 右側抽屜（Drawer） | 新增/編輯實體的表單，右上 ✕ 或送出後關閉 |
| 確認 Dialog | 刪除前必問「確認刪除？」，紅色按鈕確認 |
| Toast（右上角浮現） | 綠邊=成功、紅邊=失敗（會附上後端錯誤訊息）、4 秒自動消失 |
| 空狀態 | 機架線稿圖＋引導按鈕（例如還沒產生過結果時） |

### 3.3 數值顯示慣例

- 功率：MW 為主（設備單機為 kW）；空間：m²；功率密度：kW/m²。
- 「—」表示原廠未公告該數值（例如部分 CDU 的整機功耗），系統不會編造數字；這類設備在對應的效率評比中會排在有完整資料者之後。

## 第 4 章　配置產生器完全指南

### 4.1 表單欄位逐項說明

**A. 基本需求**

| 欄位 | 說明 | 範例／注意 |
|---|---|---|
| 資料中心類型 | AI 訓練／AI 推論／混合 AI 訓練與推論／雲端 | 決定節點型別組成（訓練=GPU+Storage；推論=CPU-GPU+CPU+Storage；混合=GPU+CPU-GPU+Storage；雲端=CPU+Storage） |
| 目標模式 | 「機架數」或「功率」 | 機架數 = 直接指定總機架數（如 10000）；功率 = 輸入字串如 `100MW`、`1GW`（系統反推機架數） |
| 模型別 | Canonical／Reference | Canonical 論文標準配置；Reference 真實系統 |
| 年份（Canonical） | 2024／2027／2029／All | 2027/2029 是高密度預測（GPU 機架 600kW/1000kW）；選 All 會三個年代各出一份結果 |
| 參考配置（Reference） | 多選核取清單 | 不勾＝全部系統各出一份；勾選＝只算選中的 |
| 優化目標 | Space／Power（至少一個） | 勾兩個 → 兩套選型並列，可切換比較 |

**B. 冷卻**

| 欄位 | 說明 |
|---|---|
| 散熱模式 | 乾式冷卻（Dry cooler，省水、戶外占地大）／蒸發冷卻（冷卻水塔，能效好） |

**C. 冗餘（七個槽位）**

每個槽位可選 N、N+1、N+2、2N，或自訂 xN/y（如 `3N/2`）。選 xN/y 時介面會即時顯示「有效容量 = y/x × 額定」。七槽位：散熱端、冰水機、CDU、PDU、UPS、MSB、備援發電機。預設：冷卻側全部 N+1、配電側全部 2N。

**D. 進階（預設收合）**

| 欄位 | 說明 | 預設 |
|---|---|---|
| 安全餘裕 | 設備超配比例 slider（0–100%） | 20%（來自全域參數 safety_margin） |
| rack_per_row | 每列機架數 | 10 |
| rows_per_pod | 每 pod 列數 | 2 |

> 這三個欄位的預設值來自「參數管理」的全域參數；在表單改只影響本次計算，在參數管理改則改變預設值。

### 4.2 範例 1：10,000 機架 AI 訓練中心（2024）

輸入：AI 訓練｜機架數 `10000`｜Canonical 2024｜其餘預設。

**預期結果**（對拍基準值）：

| 指標 | 數值 |
|---|---|
| GPU 機架 | 8,876 架／1,402.4 MW |
| Storage 機架 | 1,124 架／33.4 MW |
| IT 總功率 | **1,435.8 MW（≈1.4GW）** |
| 功率密度 | **79.77 kW/m²** |
| White space | 18,000 m² |

### 4.3 範例 2：1GW 功率目標

輸入：AI 訓練｜目標切到「功率」輸入 `1GW`｜Canonical 2024。

**預期結果**：總機架 **6,965 架**（GPU 6,182＋Storage 783）、White space ≈ **12,537 m²**。功率目標模式的邏輯是：先算參考配置的功率密度，再用 `機架數 = 目標功率 ÷ (密度 × 每架占地)` 反推。

### 4.4 範例 3：2027 高密度預測

輸入：AI 訓練｜機架數 `10000`｜Canonical **2027**。

**預期結果**：GPU 機架變 600 kW/架，IT 總功率跳到 ≈ **3.3 GW**，功率密度 ≈ 183 kW/m²——同樣一萬架，2027 的功率是 2024 的 2.3 倍（這就是論文的核心發現之一）。再切到 2029 會看到 ≈ 4.7 GW。建議用「All」一次產生三個年代再進行情境比較（見第 6 章）。

### 4.5 範例 4：用真實系統當參考（Reference 模式）

輸入：AI 訓練｜機架數 `2000`｜模型別切 **Reference**｜在參考配置清單勾「**xAI COLOSSUS**」。

系統會照 COLOSSUS 的比例（GPU:Storage = 1563:203、GPU 100kW/架 48U 正規化到 42U）縮放到 2,000 架，並算出對應的冷卻與配電。不勾任何項目時，會對清單中**每一個**參考系統各出一份結果（適合橫向比較不同真實設計）。

### 4.6 範例 5：乾冷卻 vs 蒸發冷卻

同一組輸入跑兩次（一次乾式、一次蒸發），各存成一個情境再比較：

- 乾式：散熱端需要大量乾冷卻器（例如 4,983 台小型或 628 台大型），**室外占地大**（上萬 m²）、但耗水少。
- 蒸發：冷卻水塔台數少（數十台級）、能效高（冷卻功耗占比低），適合水源充足處。

比較時看「Gray space 室外」與「冷卻功耗」兩個指標即可看出取捨。

### 4.7 範例 6：N+1 vs 2N 的影響

把 UPS 槽位從 2N 改成 N+1 再產生：UPS 台數會明顯下降（例如從 276 台降到約一半），但容錯能力也降。2N 的「有效容量 = 1/2 × 額定」是關鍵——同容量需求下要買兩倍設備。試著在 xN/y 自訂 `3N/2`：每台只交付 2/3，台數介於兩者之間。

## 第 5 章　結果儀表板解讀

產生後右側依序為：

1. **四張指標卡**：總機架數（含各型別分解）、IT 峰值 MW（含 IT＋冷卻＋損耗分解）、功率密度、White space（含 Gray 室內/室外提示）。
2. **配置/目標切換**：多配置或多優化目標時，用上方 Segmented 切換（Space／Power）。
3. **功率組成堆疊長條**：IT vs 冷卻功耗 vs 配電損耗（含安全餘裕段），滑到圖例看百分比。
4. **雙圓環**：空間分佈（White vs Gray 室內 vs Gray 室外）與機架分佈（依 nodeType）。
5. **Gray space 指標磚**：室內／室外 m²。
6. **冷卻 BOM 表**：每一類別中選的設備——型號、廠商（**台達 = 綠點**）、數量、每 pod 台數（列級設備）、總容量 MW、功耗 MW、空間 m²。hover 型號可看「在型錄中檢視」。
7. **配電 BOM 表**：分「IT 階段」（支撐 IT 負載）與「廠務階段」（支撐冷卻功耗的 UPS/MSB/Gen）兩組，含效率與轉換損耗 MW。
8. **參數快照**（摺疊）：本次計算用到的全部全域參數值（與預設不同者 cyan 標記），可一鍵複製 JSON——論文或報告引用時附上它，別人才能重現你的結果。

> 若表單改過卻還沒重跑，儀表板會出現 amber「參數已變更」徽章提醒結果是舊的。

## 第 6 章　情境管理：儲存、重開、比較

### 6.1 儲存與重開

- 產生結果後按「**儲存情境**」→ 命名（系統會預填「類型＋規模＋年份」）→ 存入資料庫。
- 頁面下方「已存情境」列表：可搜尋、依類型篩選；「**開啟**」會把該情境的輸入回填表單並回顯結果；「複製參數」快速帶入；「刪除」需確認。

### 6.2 情境比較（最多 3 個）

勾選 2–3 個情境 → 按「**比較所選**」→ 底部 Drawer 展開對照表：

- 每列一個指標（IT MW、密度、White/Gray space、各類設備數量），每欄一個情境，**最大值以 cyan 加亮**。
- 附峰值功率與空間的雙分組長條圖，可匯出比較 CSV。

**範例流程（年代演進分析）**：用範例 4.4 的方法，以 Canonical「All」分別把 2024、2027、2029 存成三個情境 → 全選比較 → 你會得到「同樣 10,000 架，功率 1.4GW → 3.3GW → 4.7GW」的完整對照表，可直接匯出 CSV 做圖。

## 第 7 章　資料庫管理（/catalog）

### 7.1 設備型錄瀏覽

- 上方 8 類**分類膠囊**（CDU／冰水機／乾冷卻器／冷卻水塔／PDU／UPS／MSB／備援發電機，含筆數徽章）。
- **廠商多選**下拉、**搜尋框**（型號或廠商，300ms 防抖）。
- 「**僅看台達電子**」綠色 Switch：只看台達 20 項產品（台達列有左綠條＋品牌徽章）。直接訪問 `/catalog?vendor=Delta` 也會自動開啟。
- 點列展開三欄詳情：完整規格／尺寸比例條／來源全文＋「以此設備產生配置 →」。
- 每筆設備附**來源 URL**（外鏈圖示），可追溯原廠型錄。

### 7.2 新增設備（範例：新增一台自研 CDU）

1. 按頁首「**＋新增資料**」（在「設備型錄」分頁）→ 右側抽屜打開。
2. 填寫：
   - 名稱：`ACME LiquidCDU 2500`、廠商：`ACME`（不存在會自動建廠商）
   - 分類：**CDU 液冷分配單元** → 表單自動顯示「峰值功耗(kW)」欄（配電類則顯示「效率(0-1)」）
   - 容量：`2500` kW、峰值功耗：`15` kW
   - 尺寸 H/W/D：`2.2 / 1.1 / 1.3` m（即時顯示比例條）、λ 維護通道比：`0.2`
   - 年份：`2026`、來源 URL：`https://example.com/datasheet`
   - engineEligible：**開**（要讓引擎選得到）
3. 儲存 → toast 成功 → 新列 cyan 閃爍。之後產生配置時，這台就會參與 CDU 選型競爭。

> 驗證規則：容量必須 > 0；效率 0–1；年份 1950–2035；URL 需合法。錯誤會紅邊提示。

### 7.3 編輯與 engineEligible

- 點列的「編輯」→ 同一抽屜改值。常見用法：把原廠缺功耗的設備補上實測值，或把某設備的 engineEligible **關掉**（型錄保留但引擎不選）。
- 種子中「機架級 rPDU／小型配電櫃」預設 engineEligible=關（它們不是 pod 級設備），需要時可手動打開。

### 7.4 IT 配置管理（範例：建立自己的參考配置）

切到「**IT 配置**」分頁 →「＋新增資料」：

- 名稱：`My Lab Cluster`、類型：AI 訓練、模型別：**Reference**
- RackSize：`48`、RackType：Cloud、floorSpace：`2.0`、Generation：`2026`
- nodeTypes 動態列：`GPU × 20 架 × 80 kW`＋（按「新增節點」）`Storage × 3 架 × 25 kW`，底部即時顯示「總機架 23 · 總 IT 功率 1,675 kW」

儲存後，產生器選 Reference 模式就能勾「My Lab Cluster」當比例模板。每張卡片也有「複製」（快速建立變體）與「用此配置產生 →」。

### 7.5 匯出

頁首「匯出」下拉：把**目前篩選結果**（含分類/廠商/搜尋條件）下載為 JSON 或 CSV，toast 會顯示筆數。

## 第 8 章　參數管理（/parameters）

### 8.1 介面

左側分類導覽（scroll-spy）：架構與設計／IT 模型／儲存估算／自訂參數。每列顯示 key（等寬字）、現值、預設值、單位、說明。

### 8.2 範例：調整安全餘裕

1. 找到 `safety_margin`（預設 0.2）→ 點數值行內編輯（或拖 slider）→ 改成 `0.3` → Enter。
2. 該列出現 amber「已修改」徽章；右側「變更紀錄」面板新增一筆（0.2 → 0.3）。
3. 效果：之後產生配置時表單的安全餘裕預設變 30%，所有設備計數的 `(1+sm)` 因子放大——例如某 UPS 從 276 台變 300 台。
4. 按 **⟲** 可單筆還原預設；頁首「還原全部預設」會逐一還原（需確認）。

### 8.3 範例：新增自訂參數

1. 「**新增自訂參數**」→ 抽屜：key 輸入 `custom_pue_target`（系統會自動帶 `custom_` 前綴；僅限英數底線，重複會即時提示）。
2. 值 `1.25`、單位 `ratio`、分類預設「自訂參數」、說明「目標 PUE（供自訂算法使用）」→ 建立。
3. 用途：在「算法管理」寫自訂公式時可直接引用 `custom_pue_target`（試算時自動帶入值）；自訂參數可刪除，內建參數不可刪（只能調值或還原）。

### 8.4 變更紀錄

## 第 9 章　算法管理（/algorithms）

### 9.1 註冊表導覽

內建 15 條算法（對應論文式 1–19 與架構方法），依分類分組：儲存估算（3）、IT 模型（5）、冗餘（1）、冷卻與配電設備（3）、架構與設計（3）。左清單選一條，右側顯示：式號（如 式 (2)(5)）、版本、公式卡（變數著色）、說明、enabled 開關、參數綁定。

### 9.2 調整內建算法

- 可改：說明、**參數綁定**（公式變數 ↔ 全域參數 key）、enabled、分類；存檔後版本號自動 +0.1（如 1.0 → 1.1，列表出現「已修改」徽章）。
- 不可改：內建核心公式（保護模型正確性）。想改公式 → 用「**複製為自訂**」產生可編輯副本。

### 9.3 試算面板（範例）

選「儲存機架估算（功率占比法）」→ 試算面板列出變數（`p, computeRacks, computeTdpKw, rackSize, nodeTdpKw`）→ 同名全域參數自動預填，其餘手填：

- `p = 0.042`、`computeRacks = 300`、`computeTdpKw = 158`、`rackSize = 42`、`nodeTdpKw = 0.708`
- 按「計算」→ 結果 **70**（⌈0.042×300×158 ÷ (0.958×42×0.708)⌉），下方逐行顯示代入過程。

### 9.4 自訂算法完整範例

**範例 A：含 PUE 的總耗電估算**

1. 「新增自訂算法」→ 抽屜：
   - key：`custom_total_power_with_pue`、名稱：`含 PUE 的總功率估算`、分類：自訂算法
   - 公式：`itPowerMw * custom_pue_target`（先在參數管理建好 `custom_pue_target = 1.25`）
   - 編輯器會**即時語法檢查**（✓ 綠／✕ 紅＋可用變數清單）；也可點「插入參數」把全域參數插入游標處。
2. 儲存後到試算面板：`itPowerMw = 1000` → 自動帶入 `custom_pue_target = 1.25` → 結果 **1250 MW**。

**範例 B：改良版儲存估算（把占比改成 6%）**

1. 在內建 `storage_from_power_proportion` 上按「複製為自訂」→ newKey 輸入 `custom_storage_6pct`。
2. 編輯副本公式為：`ceil(0.06 * computeRacks * computeTdpKw / ((1 - 0.06) * rackSize * nodeTdpKw))`（validate 通過才能儲存）。
3. 試算 `computeRacks=300, computeTdpKw=158, rackSize=42, nodeTdpKw=0.708` → **100**。

> 公式支援：`+ - * / % ^`、括號、函數 `ceil floor round sqrt abs min max log log10 exp pow sum`。公式不經 eval 執行，以白名單剖析器求值，無注入風險。

## 第 10 章　實戰工作流程

### 流程 1：規劃一座 100MW AI 推論中心

1. 產生器：AI 推論｜功率 `100MW`｜Canonical 2024｜乾式｜兩個優化目標都勾。
2. 看結果：機架數（約 29,000 架級）、CPU-GPU/CPU/Storage 分佈、Space 與 Power 兩套設備選型切換比較。
3. 存情境「100MW 推論-乾冷」；改散熱為蒸發冷卻再跑一次存「100MW 推論-蒸發」。
4. 比較兩情境：室外 Gray space（乾冷大很多）vs 冷卻功耗（蒸發低）→ 寫進你的評估報告。

### 流程 2：評估台達設備在新設計中的角色

1. 到型錄開「僅看台達電子」，確認 GoCool-1500（1.5MW CDU，GB200 NVL72 認證）與 DPH-G3-1250K UPS 的規格。
2. 產生一個高密度配置（如 Canonical 2027）。
3. 看 BOM：冷卻類 CDU 若中選台達會有綠點；UPS 在 IT/廠務階段的中選型號與台數。
4. 若想強制採用某台達型號：把競品的 engineEligible 暫時關掉再產生（或在型錄編輯競品容量/效率做 what-if）。

### 流程 3：2029 超高密度（1MW/架）可行性研究

1. AI 訓練｜機架數 5000｜Canonical 2029｜優化目標勾兩個。
2. 觀察：IT 高達數 GW、Gray space 可能達 White space 的 4–6 倍——這正是論文 §5.2 的發現。
3. 搭配冗餘調整（如散熱端 N+2）評估空間代價，存三情境比較，匯出 CSV 佐證。

### 流程 4：把自己的估算模型接進平台

1. 參數管理新增 `custom_storage_ratio = 0.06`。
2. 算法管理新增公式（引用 `custom_storage_ratio`），試算驗證。
3. 回到產生器以相同輸入跑內建模型，對照你的估算差異——平台就成為你的模型驗證工具。

## 第 11 章　FAQ 疑難排解

| 問題 | 解法 |
|---|---|
| 按「產生配置」出現「查無符合條件的 IT 配置」 | 檢查類型/模型/年份組合（Reference 的「混合 AI 訓練與推論」本身無參考系統；改用 Canonical） |
| BOM 表某設備顯示「—」功耗 | 原廠未公告該值（型錄 notes 有說明）；可在型錄編輯補上實測值 |
| 結果數字和說明書不同 | 你到過參數管理改值——「還原全部預設」再重跑 |
| 型錄改了但產生結果沒變 | 確認該設備 engineEligible 是開的；且同類中它的效率/空間效率確實勝出才會中選 |
| 自訂公式儲存不了 | 語法檢查未過（紅 ✕）——依提示修正；變數名只能用英數底線 |
| 內建算法想改公式 | 內建公式鎖定，請用「複製為自訂」改副本 |
| 刪除內建參數/算法失敗 | 內建項目只能調整或停用，不能刪除 |
| 功率字串格式錯誤 | 支援 `數字+W/kW/MW/GW/TW`（如 `500kW`、`1GW`），須為正值 |
| 其他人看的到我的修改嗎？ | 部署版所有訪客共用同一資料庫，修改即時共享（目前無登入機制） |
| 資料會因為改版消失嗎？ | Kimi 全端版：不會（資料在雲端 DB，新版本不清空）；自架版：在自己的 MySQL |
| 如何重現別人的結果？ | 請對方提供該情境的「參數快照」JSON，到參數管理逐一對齊後重跑 |
